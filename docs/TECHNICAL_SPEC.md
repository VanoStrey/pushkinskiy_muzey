# Техническая спецификация: музейный каталог и маршруты

Документ описывает текущие контракты данных, генерации маршрута и проверки пересечений с официальными экскурсиями.

## 1. Официальный каталог экспонатов

- Исходные JSON: `masterpieces.json`, `buildings.json`, `collects.json` из открытых данных Пушкинского музея. Их локальные копии в `data/raw/` исключены из Git.
- Скрипт `backend/scripts/prepare_museum_data.py` нормализует источники. `--update` загружает и проверяет набор перед заменой файлов.
- Runtime-каталог хранится в `backend/app/data/processed/` и поставляется вместе с `backend/app`; приложение после клонирования не требует `data/raw/`.
- В снимке: 97 экспонатов, 11 зданий и 61 зал. `get_exhibit_by_id()` использует реальные ID музея как строки. Связь экспоната с залом задаётся парой `(building_id, hall_id)`.
- Кандидаты берутся из выбранного здания только при наличии музейной записи, отметке `show_in_hall`, подходящем зале и незакрытом здании согласно снимку. Это не подтверждает фактическую доступность сегодня.
- Источник и инвентарный номер остаются привязаны к экспонату. Текст ограничивается 500 символами; изображения не встраиваются.

## 2. Генерация маршрута

Оба генерационных endpoint используют один генератор и один источник фактов:

### `POST /api/routes/generate`

Контракт каталожной функции. Запрос содержит `audience`, `interests`, `duration_minutes`, необязательный `building_id` (по умолчанию `116`). Ответ содержит остановки вида `{ exhibit, reason, activity }`, пояснение и примечания об использовании/доступности.

### `POST /api/route/generate`

Совместимый адаптер для полного пользовательского сценария. Запрос содержит `interests`, `duration_minutes`, `group_type`, `difficulty`, `style`. Ответ содержит `route_id`, `title`, `intro`, `is_fallback` и `stops` с реальными музейными `exhibit_id`, названием, автором/датой из каталога, расположением, ссылкой-источником, персональной причиной и заданием.

Сервис передаёт модели только отобранных кандидатов. Ответ модели принимается лишь когда каждый ID входит в набор кандидатов, ID не повторяются и число остановок соответствует доступному каталогу (обычно 4–6). Названия, авторы, даты, местоположение, инвентарные номера и ссылки ответа берутся из каталога, а не из текста модели. Если AI Studio не настроена, возвращается нейтральный маршрут с заданием-наблюдением.

Задание имеет тип `observation`, пустой список `options` и `correct_option: null`. Интерфейс позволяет отметить его выполненным и не начисляет правильные ответы. Для будущих вопросов с выбором ответа схема сохраняет тип `question`, но генератор музейных маршрутов не создаёт ответы для неразмеченных исходных данных.

## 3. Полный пользовательский сценарий

`frontend/src/pages/home/ui/home-page.tsx` сохраняет настройку предпочтений, состояние загрузки и ошибок, обзор, переход по остановкам, прогресс и экран итогов. Клиент сценария вызывает `POST /api/route/generate`. Каталожный клиент может вызывать `POST /api/routes/generate`; оба endpoint делегируют отбор и проверку одной реализации `backend/app/services/route_generator.py`.

Frontend общается с backend через относительные `/api/...` адреса и `apiPost<T>` или `apiPost<T, Body>`. `RequestInit`, включая `AbortSignal`, передаётся в `fetch`.

## 4. Официальные экскурсии и уникальность маршрута

Роутер `/api/routes` также предоставляет:

- `GET /api/routes/official` — получить снимок официальных маршрутов;
- `POST /api/routes/import-official` — повторно выполнить идемпотентный импорт;
- `POST /api/routes/check-uniqueness` — сравнить список музейных ID нового маршрута с импортированными маршрутами.

Записи сохраняются в YDB (`official_routes`) и доступны из in-memory репозитория при локальной работе без YDB. Проверка сравнивает точную последовательность, набор ID, долю пересечения/Jaccard и сходство названия.

Снимок официальных маршрутов исторически содержит slug-ID. Импортёр больше не принимает такой slug за ID музейного каталога: он сопоставляет остановку по точному нормализованному названию и автору с уникальной записью каталога. В `exhibit_ids` попадают только реальные музейные ID. Несопоставленные остановки сохраняются с `exhibit_id: null`; маршрут получает `partial` или `unverified`, а не `verified`. Совпадения по одному лишь приблизительному названию не объявляются проверенными.

## 5. Ограничения

- В доступном наборе `collects.json` нет коллекционных записей; 97 экспонатов являются снимком, а не live-каталогом.
- Официальные маршруты могут включать объекты за пределами этих 97 записей или использовать названия, не совпадающие с каталогом. Такие остановки сохраняются как несопоставленные и не входят в сравнение по ID.
- Интеграционные тесты генерации подменяют ответ `ask`; успешный тест с подменой не подтверждает доступность или правильность реального вызова AI Studio.
- Порядок маршрута тематический, не кратчайший; актуальные часы, закрытия и доступность экспонатов не проверяются.
