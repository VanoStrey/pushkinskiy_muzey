# Техническая спецификация каталога и маршрута

Этот документ описывает общие интерфейсы модуля официальных музейных данных.

## Каталог

- Источники: `data/raw/masterpieces.json`, `buildings.json`, `collects.json` с сайта Пушкинского музея.
- Подготовка: `python3 backend/scripts/prepare_museum_data.py` офлайн; `--update` скачивает все источники, проверяет JSON и только потом обновляет локальные данные.
- Runtime-файлы: `backend/app/data/processed/*.json`; они лежат внутри `app/` и попадают в Docker-образ и Cloud Function bundle вместе с `cp -r app`.
- `get_all_exhibits()` возвращает список каталога; `get_exhibit_by_id(id)` ищет по строковому музейному ID; `get_route_candidates(building_id="116")` возвращает только записи с названием, известным незакрытым зданием, разрешённым залом в этом здании и `show_in_hall=true`.
- Зал связывается ключом `(building_id, hall_id)`. API отдаёт посетительский номер и название зала, а не подменяет их техническим ID.

## HTTP API

### `GET /api/exhibits`

Параметры: `building_id` (по умолчанию `116`), `route_eligible_only` (по умолчанию `true`). Ответ содержит `count`, `items`, название здания и примечание об атрибуции. В каждой записи `id` — строка; `hall` содержит `number`, `name`, этаж и `floor_plan_url`.

### `POST /api/routes/generate`

Запрос:

```json
{
  "audience": "подростки, впервые в музее",
  "interests": ["Древний Египет", "мифы"],
  "duration_minutes": 45,
  "building_id": "116"
}
```

AI Studio получает только каталог кандидатов и контекст запроса. Оно возвращает ID и короткие пояснения остановок. Бэкенд отвергает неизвестные и повторные ID, затем дополняет остановки сведениями из каталога. При менее чем четырёх кандидатах запрашиваются все найденные; при отсутствии кандидатов возвращается пустой маршрут с пояснением.

Маршрут не утверждает кратчайший путь. `show_in_hall` и `building.closed` не подтверждают реальную доступность посещения.

## Атрибуция и использование данных

Описание и аннотация очищаются от HTML и ограничиваются суммарно 500 символами на экспонат. API и интерфейс показывают источник с прямой ссылкой на карточку музея. Изображения не встраиваются; в подготовленном JSON остаются только исходные URL изображений. Полные исходники сохранены локально для повторяемой подготовки и не должны публиковаться без отдельной проверки прав.
