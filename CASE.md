# Кейс: персональный AI-маршрут по Пушкинскому музею

## Контекст

Музей — это сотни залов и тысячи экспонатов. Семья с детьми, турист, который пришёл впервые, и знаток искусства ищут в нём разное. У них разное время, разные интересы и разный язык. Один на всех маршрут никому не подходит идеально.

## Задача

С помощью вайбкодинга и **Yandex AI Studio** сделать работающий прототип сервиса, который строит **персональный маршрут по Пушкинскому музею** для заданной целевой аудитории.

Каждая команда случайно получает свою целевую аудиторию, например:

- родители с детьми;
- туристы, которые пришли впервые;
- студенты;
- люди, которые редко ходят в музеи;
- знатоки искусства.

Точный список определяют организаторы.

Цель — не просто подобрать экспонаты, а понять, **каким должен быть музейный маршрут для этой аудитории**, и с помощью ИИ превратить данные об экспонатах в понятный и цельный пользовательский опыт.

## Основной сценарий

1. Пользователь открывает сервис.
2. Вводит параметры: кто пришёл, сколько есть времени, что интересно.
3. ИИ обрабатывает запрос.
4. Пользователь получает маршрут.

Для каждого объекта маршрута можно показать:

- название;
- изображение, если оно есть;
- краткую справку;
- рассказ, адаптированный под аудиторию;
- почему объект включён в маршрут;
- дополнительную информацию или интерактив (квест, загадка, поиск улик).

Формат подачи команда выбирает сама.

## Роль ИИ

Персонализация строится на трёх вещах: **выпавшая аудитория + параметры пользователя + данные об экспонатах**.

AI Studio должна играть в сервисе содержательную роль, а не только писать описания. Например:

- разбирать запрос пользователя;
- выбирать экспонаты;
- определять порядок обхода;
- адаптировать рассказы под аудиторию;
- объяснять, почему объект попал в маршрут.

## Обязательно в MVP

1. **Работающий интерфейс.** Интерактивный сайт, а не слайды.
2. **Yandex AI Studio** формирует персональный результат.
3. **Реальные данные музея** из общего датасета. В маршруте только объекты, которые есть в датасете.
4. **Адаптация под выпавшую аудиторию.**

Сильные команды могут использовать мультиагентные сценарии, Yandex Workflows, YDB, Object Storage и другие сервисы Yandex Cloud. **Сложная архитектура не требуется и баллов не добавляет.**

## Музей - это интересно, 

Для некоторых категорий посетителей можно применять **игровые механики:** квесты, загадки, поиски улик. 

Финальная проверка: соседняя команда открывает сайт по QR-коду и проходит сценарий «вслепую», зная только целевую аудиторию (без дополнительных подсказок автора)

## Данные

- Единый [открытый датасет](https://pushkinmuseum.art/open_data/index.php?lang=ru) объектов Пушкинского музея: описания, в части объектов есть изображения.
- Ссылку на датасет и описание формата выдадут организаторы *(уточняется)*.
